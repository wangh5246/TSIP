# WayBill 外部审阅报告（2026-07-13）

- 文件性质：用户提供的 WayBill/RUC 审阅报告，共 759 行。
- 本笔记用途：保留审阅意见的结构化事实源；判断和路线已提升到 [[Knowledge/WayBill-v6方法优化决策]]。
- 保真边界：以下为审阅报告的归纳，不代表所有结论已由仓库 artifact 独立验证；交叉核验见 [[Sources/Docs/WayBill当前仓库审计-2026-07-13]]。

## 总体结论

审阅报告建议 **major revision**。核心问题不是措辞，而是 trusted sensing 语义、fallback 公平性、城市规模证明、E3 严格性、部署证据和隐私评估仍不足。报告认为论文有可保留的系统框架和实验基础，但不宜直接进入投稿写作。

## 主要阻断项

### 1. 可信输入语义过强

- OSNMA 认证的是导航消息，不等同于认证接收机的物理位置。
- tachograph/odometer 的制度存在不等同于分钟级轨迹已被安全认证。
- 论文应把导航消息认证、接收机输出完整性、位置有效性、里程计可信度和物理位置真实性分层表述。
- 若保留部署性主张，应增加真实接收机与里程计的小规模现场实验。

### 2. 时间型 fallback 对诚实用户不公平

当前规则 `Δt × v_max × r_max` 会把停车或长时间 dwell 当作按最高速度行驶，造成极端 surcharge。报告建议：

- 正常定位区间：`Δodo × zone rate`；
- 定位不可用区间：`Δodo × r_max`；
- 整段或周期缺失：用月度 odometer 做未覆盖里程 reconciliation；
- 连月度 attestation 也缺失：进入行政处理，而非继续假装为纯密码学结算。

同时增加两侧性质：Revenue Soundness 与 Honest-user Fairness。

### 3. tariff tree 容量与城市数据不一致

- 当前 depth 8 只有 256 个叶子。
- GeoLife/城市实验约有 10,000 个 tariff cells，至少需要 depth 14 才能直接容纳。
- 建议基准矩阵：depth 8/12/14/16 × fixes 25/50/100/200。
- 至少要在 depth 14 上完成真实 proof generation 和 verification，不能只报告约束数。

### 4. E3 缺少收敛或最优性证据

- 现有 bucket refinement 能说明离散化敏感性，但未给出 solver convergence、admissible relaxation 或 optimality gap。
- 报告特别指出 Rome 在 100 m → 50 m 时，P95 从约 0.464 降到 0.295；这说明 bucket 选择显著影响结论。
- 应同时记录可行攻击值和合法上界，并给 gap；在此之前不应称形式化 upper bound。

### 5. E4/E5 的现实语义不足

- E4 的 camera count 是 100 m segment equivalents，不是真实站点数；应基于候选点位做 set cover。
- E5 的 pool equivalence 不等同于匿名性；需要 route inference、跨期 linkability 和少量 opening 后的可识别性。
- 报告注意到精确匿名中位数为 1，且一次较粗 opening 会大幅去匿名，说明现有隐私结论需收缩。

### 6. 真实经济与基线证据不足

- 使用真实 tariff 和真实月度账单，报告绝对金额误差与相对误差。
- 若保留对 TEE 的绝对比较，需要完整实现和相同威胁模型；否则删除绝对结论。
- 增加完整 reproducibility、限制和部署假设。
