# M4 — 服务器正式大规模实验

## 决策与范围

本卡是 WayBill V6 正式服务器实验的唯一执行规格。已批准采用“方法与安全论文
主线”：S1–S4 构成主论文证据，S5 只补系统执行性；不做无匹配功能的 TEE 绝对
比较，不用 smoke、缩小数据、减少 seeds、synthetic-only、compile-only 或只保留
成功实例替代正式结果。

就绪性事实与阻断项见
[[Results/Reports/服务器正式实验就绪性审计-2026-07-15]]；已验证的方法基线见
[[Results/Reports/V6方法门禁与实验台账-2026-07]]。

## 正式实验定义

以下条件缺一项，该运行只能标记为 `debug/preflight`，不得进入论文聚合：

- 使用冻结且干净的 Git commit/tag、容器 digest、配置 hash 和输入 manifest；
- T-Drive、GeoLife、Porto、Rome 均从完整授权源生成，预处理不设开发 cap；
- `max-trips=0`、`max-raw-points=0`、`limit-per-input=0`、`max-fixes=0`；
- 所有预注册 dataset/config/seed 单元都有 pass/fail/timeout receipt，不能删除失败项；
- 输出目录由 `protocol_id/run_id` 唯一标识，已有运行不可覆盖；
- 统计只读取严格 aggregate receipt，不从日志手工挑选数字；
- 服务器环境检查可以先执行，但不产生论文结果，也不算简化实验。

## S1 — 全量 fallback、公平与收益安全

### 输入与样本规则

- 数据集：完整 T-Drive、GeoLife、Porto、Rome；使用所有通过预注册清洗规则的
  periods，不设 per-dataset/per-user cap。
- 统计单元：按原始 vehicle/user 聚类；period 不能伪装成独立用户。
- 方法：`oracle-position`、V5 `Δt×v_max×r_max`、V6
  `Δodo×r_max`、V6 `without-month-close`。

### outage 与误差矩阵

1. 自然 gap/outage，完全保留数据中的原始可审计模式；
2. 独立 mask：`α={0.05,0.10,0.20}` ×
   `seed={17,31,47,73,101}`；
3. burst mask：总 outage share 固定为 0.10，连续长度
   `{1,3,10}` fixes × 同一组 5 seeds；
4. odometer sensitivity 为独立 V6-only 矩阵：
   `error={-2%,-1%,-0.5%,0,+0.5%,+1%,+2%}`，分别在 natural 与
   `α=0.10` 的 5 seeds 上运行。

### 指标与门禁

- undercharge、withholding advantage、surcharge mean/median/P95/P99；
- 绝对实验货币与相对比例同时报告，Rome/dwell-heavy 单列；
- parking false distance/fee、month-close uncovered/double-count、reject rate；
- vehicle/user-cluster bootstrap 95% CI，分数据集与 pooled 均报告；
- 任何 V6 undercharge/withholding/double-count/parking false fee 超出冻结误差界，
  S1 失败；不能用平均改善掩盖安全失败。

## S2 — 完整二维 Groth16 规模与并发

### 主矩阵

- `depth={8,12,14,16}` × `fixes={25,50,100,200}`，16/16 配置全部执行
  compile、setup、witness、prove、verify；
- 每配置 1 次 warm-up + 10 次 measured trials，10 份 proof hash 必须互异；
- 每配置执行 tariff root、profile commitment、bill/public signal 和私有 Merkle path
  负测；
- depth 14/16 绑定同一 10,000-cell artifact；depth 8/12 使用有独立 provenance
  manifest 的 capacity-matched tree，只比较计算成本，不比较经济语义；
- setup 仅执行一次并记录完整 key verification；非主张 key 只在证明和 receipt
  聚合全部结束后清理。

### 并发压力

- 配置：depth 14 × fixes `{100,200}`；
- 并发：`{1,2,4,8}`，若 8 超过目标节点可安全容纳的并行 proof memory，则该单元
  记录 resource-rejected receipt，而不是静默降到 4；
- 每个并发档 5 个独立 batch；主 latency 表使用隔离 job，并发表单独报告吞吐、
  P50/P95/P99、RSS、CPU utilization 和失败率。

### 主张边界

normalized tiers 只支持 computational capacity claim。没有现实 per-distance tariff
时，不得把 S2 写成真实经济账单、生产可信设置或 production-security certification。

## S3 — 全量 certified attack bounds

- canonical instance corpus 从 S1 的所有合格 periods 生成，不再使用
  `legacy_adapter` 作为主结果；
- `bucket={100,50,25,10} m` × attacker/relay radius `{50,100,200} m`；
- `limit-per-input=0`、`max-fixes=0`，每个 instance 单独进入 job array；
- 每实例 timeout 为 7200 s；timeout 仍保留 best feasible、best bound、gap、资源和
  `unresolved_timeout` receipt；
- fixes ≤5 的实例运行 independent exact oracle，其余实例运行 strict feasible
  checker 与合法 relaxation；
- 100% 预注册实例必须有 receipt，任何 `LB>UB`、非法 feasible 或错误 containment
  立即使整个 S3 失败；
- 强主张门槛：每个预注册主 stratum representative relative gap ≤1%，全实例至少
  95% certified 且 gap ≤5%。未达到时完整报告 gap/timeout CDF，并降级主张，不删除
  困难实例。

## S4 — route inference 与跨期 linkability

### 观察视图

- O0：当前协议实际公开的 public signals；
- O1：O0 + period-level fallback indicator；
- O2：O1 + period distance/amount bucket；
- O3：O2 + 随机 opening 比例 `{1%,5%,10%}`。

若实际接口字段与上述假设不同，先由 schema 自动生成 observation manifest，再冻结
矩阵；不得手工添加协议中并未公开的信息。

### 正式矩阵

- 四个完整真实数据集；连续 proof-period horizon `{1,4,12}`；
- opening `{0%,1%,5%,10%}`；
- attackers：random/majority baseline、nearest-route matcher、监督式 linker；
- seeds `{17,31,47,73,101}`，train/test 按 vehicle/user 隔离；
- 指标：top-1/top-5 route or identity accuracy、linkability AUC、精确等价集分布、
  opening 后可识别比例及 95% CI。

该实验没有“必须隐私良好”的通过阈值；攻击成功也是有效结果，但必须触发 claim
downgrade。没有 S4 时，不得写“pool size 证明 route anonymity”。

## S5 — 端到端系统补充

S5 不替代 receiver/odometer field trial，也不进入 S1–S4 的方法硬门：

- verifier microbenchmark：fixes `{25,100,200}`，100 份互异有效 bundle 组成固定
  corpus，每配置 10,000 次 verifier 调用；
- charger acceptance：每 fixes 配置至少 100 份互异 period/profile-bound proofs；
- concurrency `{1,8,32}`；workload 为 100% valid、95/5 valid/tampered、
  90/5/5 valid/tampered/replay；每单元 3 次完整运行；
- 报告 correctness、P50/P95/P99、throughput、RSS、replay/tamper rejection；
- 不得使用旧 RiseFL/TSIP Docker 栈的结果冒充 WayBill V6 charger 结果。

## Artifact 与不可覆盖规则

正式输出根固定为：

`experiments/waybill_server_formal/<protocol_id>/<run_id>/`

每个 run 必须包含：

- `protocol.json`、`environment.json`、`code_manifest.json`、`data_manifest.json`；
- `jobs/expected.jsonl` 与每 job 的 immutable attempt receipt；
- `S1/` 至 `S5/` 原始结果、严格 aggregate、图表输入和 claim boundary；
- `status.json` 只能由 validator 生成；任一 expected unit 缺失时不得为 pass；
- 重试使用新的 attempt id，不能覆盖首次失败；聚合器按预注册规则选择首次成功或
  报告全部尝试，不能手工选择最快结果。

## 执行顺序与停止规则

1. RG0–RG5、RG7、RG8 在本地/CI 关闭；
2. 在目标服务器运行 RG6，全部通过后生成 formal run ID；
3. 先运行 S1 数据与统计，再运行 S2、S3 job arrays；S4 在 observation schema
   冻结后运行；S5 最后运行；
4. 任一输入 hash、代码 hash、容器 digest 或 expected cardinality 不一致，立即停止；
5. 不因 timeout/OOM 无限提高资源。每个 job 默认最多 2 次 attempt：原配置一次、
   相同配置的恢复重试一次；第二次失败保留 unresolved；
6. 禁止在正式运行过程中改变 datasets、seeds、方法、timeout 或过滤规则。
