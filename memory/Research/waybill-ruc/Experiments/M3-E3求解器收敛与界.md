# M3 — E3 求解器收敛与界

## 研究问题

能否把现有 bucket attack search 升级为有正确数学方向的 certified analysis：对最大 underpayment 同时给 feasible lower bound、relaxation upper bound 和 optimality gap？

方法决定：[[Knowledge/WayBill-v6方法优化决策]]  
V5 证据：[[Results/Reports/V5证据快照与审阅差距-2026-07]]  
V6 台账：[[Results/Reports/V6方法门禁与实验台账-2026-07]]

## 先冻结问题定义

明确：

- attacker 可修改/隐藏的观测；
- displacement 半径、速度、cadence、map-matching 和 attestation 约束；
- tariff function 与账单真值；
- objective 是 absolute underpayment、relative underpayment 或二者；
- period coupling、checkpoint continuity 和 rounding 是否进入优化。

所有 solver 必须优化同一 SSOT objective。若 100/50/25/10 m bucket 对应的可行域没有包含关系，不能把数值单调变化解释为 bound convergence。

## 假设

通过精确小实例校验、可行解构造和合法 relaxation，可以把现有“找到了多大攻击”升级为“最坏攻击位于多窄区间内”。bucket refinement 会缩小离散化误差，但只有在给出误差或集合关系证明后才具有 bound 含义。

## 三层求解器

### L0 — Exact oracle for small cases

- 对小 cell/fix 实例穷举或动态规划；
- 输出全局 optimum；
- 用于验证 objective、约束、rounding 和后续 solver 方向。

### L1 — Feasible attacker

- MILP incumbent、A*/B&B 完整路径或现有 bucket 解映射回原问题；
- 必须逐约束验证，形成 feasible certificate；
- 对最大化 underpayment，它是 optimum 的 lower bound。

### L2 — Proven relaxation

- 明确删除/放松哪些约束，证明原可行域包含于 relaxation；
- 求 relaxation optimum 或合法 dual/bound；
- 对最大化问题，它是 upper bound。

报告：`LB = feasible attack`、`UB = relaxation bound`、`abs_gap = UB-LB`、`rel_gap = (UB-LB)/max(|LB|, ε)`。

## 实验矩阵

### Bucket convergence

- bucket：100、50、25、10 m；
- 数据集：现有 E3 全部数据集，Rome 单列；
- 至少覆盖 low/median/high tariff heterogeneity 与短/中/长 period；
- 固定 seeds、attacker budget 和 timeout。

### Solver cross-check

- small oracle vs MILP/B&B：optimum 必须一致；
- existing heuristic vs feasible checker：不合法解必须拒绝；
- relaxation bound vs exact oracle：不得低于 exact optimum；
- 不同 solver/backend 对代表实例交叉验证。

### ρ-robust tariff envelope（条件分支）

- `ρ` 取 threat model 允许的 displacement；
- 比较 original tariff 与 `r_ρ`；
- 测攻击 underpayment、诚实 surcharge、边界受影响比例和 tariff root 变化；
- 只有理论与公平门禁同时通过才提升为方法贡献。

## 指标

- LB、UB、absolute/relative gap；
- time to first feasible、time to best bound、总 runtime；
- explored nodes、memory、timeout 状态；
- 不同 bucket 的 value/gap 变化；
- attack feasibility violation count；
- robust envelope 的最大 underpayment、median/P95 honest surcharge 和 affected-user share。

## 统计与报告

- 每个实例保留 best feasible 和 best bound，即使 timeout。
- 报告完整 gap 分布，不只挑 solved cases。
- Rome 100 m → 50 m 的 P95 0.464 → 0.295 作为 regression target 重新生成，不直接复制旧文档。
- 把 absolute currency 与 relative percentage 同时报告。
- solver 参数、版本、线程数、MIP gap、timeout 与 hardware 全部进入 manifest。

## 硬门槛

- 所有 small oracle 实例中，feasible solver 找到 exact optimum，relaxation bound 不低于 optimum。
- 每个报告的 LB 都通过原问题逐约束 checker。
- 每个报告的 UB 都有书面 relaxation proof 和机器输出；无证明的数字标为 heuristic estimate。
- 论文主代表实例 relative gap ≤ 1%；其余 certified 集全部 ≤ 5%，超过者明确标为 unresolved，不进入强上界主张。
- 100/50/25/10 m 全矩阵保留 runtime 与 gap，包括 timeout。
- 不再使用“formal upper bound”描述只有 bucket sensitivity 的结果。

若发现 relaxation 方向错误或 UB 低于 exact optimum，立即停止结果汇总，M3 状态为 `failed`，先修模型。

## 执行结果（2026-07-14）

### 门禁判定

M3 对冻结模型 `e3-v6-fixed-odo/v1` 和当前认证矩阵为 **verified**。判定 SSOT
是 `experiments/waybill_m3/v1/summary.json`，逐实例证书位于
`experiments/waybill_m3/v1/bound_receipts.jsonl`，表格视图位于
`experiments/waybill_m3/v1/summary.csv`。

- 共 attempted 24 个实例，24/24 为 `certified`：GeoLife、Porto、T-Drive
  各 1 个 period × 4 个 bucket，Rome 为 low/median/high heterogeneity 三个分层
  period × 4 个 bucket。
- 100/50/25/10 m 四档全部保留；24/24 均 `LB=UB`、`gap=0 cents`、
  `relative_gap=0 ppm`，无 timeout。所有 LB 均通过原问题 strict checker，所有 UB
  方向检查通过，主代表实例 ≤1% 与其余实例 ≤5% 的门槛均通过。
- 每条 UB receipt 都记录
  `F_center ⊆ F_continuous ⊆ R_rect ⊆ R_ind` 的 containment proof；细网格
  witness 提升到粗网格时保持精确 claimed point 和 rate，仅在粗实例 strict checker
  再次接受后才作为 feasible incumbent。
- 主汇总内部 `summary_hash`（按 schema 排除自引用字段后计算）为
  `162dae920458bed6f6030981f48bf39a59f8a516f8982fbfa5b27df4e67c1666`；
  runner code hash 为
  `ebf5ce739af945b06d892f530f8734bc1df9d179edf700cf96fef669a3ee677e`。
- `summary.json` 现同时固定 Python/platform/CPU、实际命令、pure-Python solver
  backend 与串行执行/线程语义；receipt 保留 runtime、timeout 和峰值内存。

### Small oracle 与方向审计

- 独立 small-oracle gate 在原始整数点域 `F_continuous_integer` 上穷举完整，结果
  `LB=0, OPT=90, UB=90 cents`，满足 `LB≤OPT≤UB`。该实例刻意让 non-center
  点优于 center，证明 oracle 没有退化为 center-only。当次运行的 receipt
  hash 由 `summary.json` 记录；由于 receipt 包含 runtime/峰值内存，不在本卡硬编码
  一个跨重跑不变的值。
- “feasible solver 与 exact optimum 一致”的独立可复现 cross-check 由
  `tests/test_e3_certification.py::test_certified_bounds_bracket_independent_small_oracle`
  覆盖；non-center regression 则由
  `test_small_oracle_is_exact_on_original_integer_points_not_center_only` 覆盖。前者检查
  `LB=OPT=UB=90`，后者专门检查 exact oracle 的独立性，两者职责不能混写。

### Legacy 回归结论

- 旧 Rome P95 `0.464 → 0.295` 只能归类为
  **legacy bucket sensitivity**，不是 LB、UB 或 certified gap，未复制进本次认证结果。
- 旧 `648 m → 361 m` 里程投影在冻结 V6 SSOT 下被 strict checker 以
  `ODO_BINDING` 拒绝，因此旧结果与本次 certified result **不可直接横向比较**。

### 证据边界与主张降级

- 本卡只认证固定 odometer、固定攻击模型与当前 24 个实例；不能外推为所有轨迹、
  所有 attacker budget 或现实部署的全局最坏界。
- 当前输入通过 `legacy_adapter` 构造实验 tariff；它不是 M2 的 canonical 10000-cell
  tariff root，也不是现实 RUC/每米费率主张。M2 与 M3 的 tariff 证据不可互换。
- `ρ`-robust envelope 分支没有进入本次 verified 范围，不能据此声称已经证明
  bounded-displacement non-undercharge 或完成公平性评估。
- 若 strict checker、containment chain、`LB≤OPT≤UB` 或任一 UB 方向检查失效，
  本卡必须立即降级为 `failed`；未通过 gap 门槛的新增实例必须标为 unresolved，
  不得进入强上界主张。

## ρ-envelope 进入主方法的附加门槛

- 完整证明 bounded displacement 下的 non-undercharge 性质；
- envelope root 纳入 [[Experiments/M0-Canonical-Policy-Binding]]；
- 所有数据集报告诚实 median/P95 surcharge 与边界群体分布；
- 与原 tariff、细粒度 map matching 和至少一种软边界方案比较；
- 若收益安全改善只靠不可接受的普遍 overcharge，则保留为消融，不进入主方法。

## 停止与升级规则

- 不为追求低 gap 无限增加 timeout；先按实例规模分层，并保留 unresolved class。
- 若 exact formulation 在真实规模不可解，可用 certified interval 支撑有边界的结论，但必须报告区间宽度。
- 只有模型方向、oracle、feasible checker、relaxation 和 gap 门槛全部通过后升级为 `verified`。
