# 服务器租用前就绪收口（2026-07-16）

## 结论

**租服务器之前能够在本地完成的正式实验前置条件已经完成，可以进入服务器租用与目标机
验收阶段。** 这不等于正式结果已经开始：RG6 必须在实际服务器上通过，完整 prepared
corpus、S3 cardinality 和最终资源计划也必须在该服务器上物化并冻结。只有这些目标机
步骤通过后，才生成 formal run ID 和提交 S1–S5 正式作业。

调度、负测和发布门禁；服务器阶段仍只接受

## 服务器规格

首台服务器按以下规格租用：

- Linux x86_64，Ubuntu 24.04 LTS 或 22.04 LTS；
- 32 vCPU、128 GiB RAM；
- 1 TiB 高性能 SSD/NVMe 云盘，正式硬门最低 500 GiB 空闲；
- 不需要 GPU；
- 公网只开放来源受限的 SSH 22，数据盘与实例设置删除保护；
- 计费先用按量计费；RG6、全量预处理和最终计划完成后，再决定是否转包月或扩多节点。

如果全量 `plan.json` 的存储需求加 25% 余量超过 500 GiB，先扩盘；如果 S3 数量使单机
墙钟时间不可接受，再扩为 2–4 个同构节点或 Slurm/批处理队列，不改变任何实验组合。

## 租到服务器后的唯一顺序

1. 创建实例、SSH key、安全组和 1 TiB 数据盘；
2. 安装 Docker Engine，clone `waybill-formal-readiness-v1`；
3. 上传四数据集与 4.83 GB PTAU，验证 raw manifest、PTAU bytes/BLAKE2b；
4. 构建/拉取固定 digest 镜像，运行 RG6；
5. 无 cap 预处理四数据集并生成每 period 的 12 个 S3 canonical variants；
6. 冻结最终 `expected.jsonl`、CPU-hour、存储和峰值内存；
7. 若资源门禁仍通过，初始化 immutable run；
8. 依次提交 S1、S2-main、S3、S4、S2-concurrency、S5-corpus、
   S5-verifier/S5-charger；
9. 最多恢复重试一次，最后 strict merge；缺失、timeout、OOM 和失败均保留。
