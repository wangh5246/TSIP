## 最终裁决

WayBill V6 **可以作为一篇顶会论文的正式预备项目继续推进**。研究问题成立，M0–M3
形成了相互依赖而非拼接式的技术主线，S1–S4 也能直接回答安全、经济公平、规模、
最坏攻击和隐私泄漏五类核心审稿问题。现有本机资源证据没有显示不可跨越的算法或
算力障碍；当前未通过项均有明确、可机器验收的关闭路径。

但该裁决不等于“现在即可开跑”或“现在即可投稿”：

- **研究与实验可行性：通过**；
- **顶会论文预备性：有条件通过**；
- **正式服务器立即开跑：不通过，继续保持 No-go**；
- **当前稿件投稿成熟度：不通过**。

因此，准确表述是：**方向可行、方法基础可行、正式矩阵有论文价值；执行前置条件尚未
全部满足，论文也仍处于 major-revision 级预备阶段。** 服务器 readiness 仍以
[[Results/Reports/服务器正式实验就绪性审计-2026-07-15]] 的 RG0–RG8 为准。
唯一正式矩阵为 [[Experiments/M4-服务器正式大规模实验]]。

## 为什么实验矩阵具有论文价值

### S1：不是普通精度实验

S1 同时比较 oracle、V5、V6 与去掉 month-close 的 V6，并覆盖 natural/random/burst
outage、odometer sensitivity 和 user/vehicle cluster CI。它能把 M1 的定理条件、收益
安全与诚实用户代价放在同一张因果表中；`without-month-close` 是证明 completeness
贡献不可替代的关键消融。

### S2：不是只报 constraint count

16 个 depth×fixes 配置全部做真实 setup/witness/prove/verify，每配置 10 次独立测量，
再单列并发吞吐，能够回答 city-domain capacity、客户端成本和服务端验证可执行性。
现有本机 M2 已证明路线可跑通；正式服务器实验补的是 Linux 可复现性和统计可信度，
不是重新赌方法能否工作。

### S3：把攻击结果从案例提升为证书化分布

当前 24/24 certified、gap=0，且 radius=200 m 已在 30 s timeout 内通过，说明求解框架
可执行。正式 S3 的价值在于把全部 canonical periods × 4 buckets × 3 radii 变成
feasible/bound/gap/timeout 的总体分布。真正的资源风险是全量 corpus cardinality 尚未
物化；RG7 必须先生成 expected job count 与 CPU-hour/storage estimate，不能凭 24 个
实例线性外推。

### S4：决定论文能否在隐私审稿中站住

近期 PPETC 研究已经表明，即使只泄漏账单和公开收费结构，也可能恢复访问站点或
轨迹候选。因此 WayBill 不能以“没有上传 raw route”直接推出隐私。S4 必须对实际
公开字段执行 route/identity inference、cross-period linkability 与 opening 比例攻击，
并允许攻击成功触发 claim downgrade。

## 新颖性定位复审

相关工作交叉检查支持以下边界：

- [VPriv（USENIX Security 2009）](https://www.usenix.org/legacy/event/sec09/tech/full_papers/popa.pdf)、
  [PrETP（USENIX Security 2010）](https://www.usenix.org/conference/usenixsecurity10/pretp-privacy-preserving-electronic-toll-pricing)
  与 [Milo（USENIX Security 2011）](https://www.usenix.org/conference/usenix-security-11/phantom-tollbooth-privacy-preserving-electronic-toll-collection)
  为 spot-check/roadside completeness 提供了直接历史基线；
- [P4TC（PoPETs 2020）](https://publikationen.bibliothek.kit.edu/1000122915/86372068)
  已经给出严格安全模型、原型与现实硬件性能，WayBill 若投顶会必须达到相近的模型
  清晰度，不能只用测试代替安全定义；
- [2025 年 ZK vehicle taxation / subsidy work](https://arxiv.org/abs/2506.16812)
  说明“ZK + 车辆税收/区域合规”本身已不是可安全使用的 first claim；
- [PoPETs 2024 的 Brisbane case study](https://petsymposium.org/popets/2024/popets-2024-0014.pdf)
  证明最小账单信息也可能支持轨迹/站点推断，直接强化了 S4 的必要性。

推荐的核心新颖性表述是：在明确的可信测量假设下，把 **authority-pinned tariff
settlement、odometer-backed outage/whole-period completeness 和 proof-only charger**
组合为不依赖 roadside completeness infrastructure 的 zone-based RUC，并同时量化
计算、经济攻击与公开元数据泄漏边界。该表述仍需完整 related-work table 和形式化
security game 才能最终使用 “first”。

## 顶会前仍必须解决的论文级问题

1. **形式化安全模型**：把 policy authority、receiver/odometer、prover、charger、
   attacker 与 key compromise 分开；给出 acceptance/billing soundness/completeness
   game，而不只是一段 proof sketch。
2. **position-valid attestation 语义**：当前电路把 `position_valid` 绑定进 interval
   root，root attestation 又签整个 statement commitment。论文必须明确 receiver 是否
   验证并认证 availability evidence；若只是签 opaque statement，则不能模糊声称测量
   源独立认证了该 bit，也不能无条件声称 TCB “never bills”。
3. **现实 tariff 与真实单位**：M2 的 5/10/12 normalized tiers 只能证明容量；S1 的
   经济主表需要可追溯 per-distance tariff，或把所有金额降级为 normalized utility。
4. **S1–S4 正式结果**：当前 226 periods、24 instances 和 depth-14 三次测量只能作为
   方法门证据，不能进入论文主表冒充大规模正式结论。
5. **隐私攻击与 mitigations**：S4 必须先于强 privacy claim；攻击成功是可发表结果，
   但需要缩小公开字段或降低主张。
6. **真实部署证据边界**：若保留 production/deployable/real-world receiver 表述，需
   receiver+odometer field validation；若不做现场实验，必须把结论限定为 prototype
   feasibility under attested-sensing assumptions。
7. **完整稿件与 artifact**：清除 V5 遗留数字和 TODO，启用可核验 bibliography，建立
   claim→assumption→theorem/test→artifact 表，并从 clean clone 复现。

## 可行性与开跑决策

当前没有证据表明 M4 在算法上或资源上不可行：M2 已覆盖最重的 16 个 setup，M3 在
当前代表实例上有短时证书，4.4 GiB 级原始数据也不是服务器存储瓶颈。剩余问题属于
版本冻结、依赖封装、数据完整性、矩阵编排、现实语义和目标主机验收，均可工程化关闭。

因此项目应继续，但顺序必须是：

1. 关闭 RG0–RG5、RG7、RG8，并物化 S1–S5 cardinality/resource plan；
2. 在目标服务器关闭 RG6；
3. 只有 RG0–RG8 全部产生机器 receipt 后，生成 formal run ID 并一次性执行完整矩阵；
4. 同步写 Method/Threat Model/Related Work，Evaluation 主表等待 strict aggregate；
5. S1–S4 和全文安全/隐私边界通过后，才称“顶会投稿候选”。

## 一句话结论

**WayBill V6 已具备顶会论文的研究骨架和正式大规模实验方案，所有剩余前置条件均有
可行关闭路径；但这些条件尚未全部通过，所以当前是“顶会预备项目成立”，不是“服务器
已就绪”或“论文已就绪”。**
