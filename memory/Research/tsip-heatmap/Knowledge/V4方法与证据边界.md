# V4 方法与证据边界

## 方法恢复

V4 源码曾只剩 `circuit_bench/20260504_v4` 的 witness/public receipts，而仓库可编译源码仍是 13-public-input V3。2026-07-09 在 `TSIP_heatmap_version/method_code_v4_isolated/` 恢复独立 V4 source，并对保存样例完成 public-signal exact match。

恢复后的 k6/k30 circuit 均为 14 个 public inputs、23 个 private inputs、2728 个 non-linear constraints。它比历史 receipt 的 3056 constraints 更小，因此历史 receipt 只作为性能历史，当前独立目录是 regenerated optimized source。

## Artifact 分层更新 2026-07-13

上述 2,728/14/23 描述的是 archive-compatibility V4 relation，用于复核保存的 14-public-input receipts。它不是当前 Docker manifest 选择的 paper circuit。

`docker_v4_smoke/manifest.json` 绑定 `tsip_main_v4_paper_k6.r1cs`。对该 R1CS 运行 `snarkjs r1cs info` 的结果为：

- 3,547 constraints
- 16 public inputs
- 25 private inputs
- 3,550 wires

因此论文中的 3,056 constraints、14 public inputs 和 23 private inputs 不能继续作为当前 paper artifact 数字。后续必须分别标注 archive compatibility evidence 与 manifest-bound paper evidence，不得混用性能、proof ordering 或 setup receipt。

2026-07-13 Task 4 已把 canonical `TSIP/main.tex` 对齐到生成宏，并在 RQ6 固化三层事实：2,728/14/23 是 archive compatibility；3,056/14/23 及其 2026-05-04 snarkjs 延迟和 128 B proof object 是 historical benchmark；3,547/16/25 是 manifest-bound paper relation。当前 manifest 没有 serializer size receipt，因此不再声称当前 report frame 为 5,694 B，也不把任何 pre-manifest latency/throughput 移植到当前 relation。

## C21 Route-B binding

核心关系为：

- `primary_commitment = Poseidon(payload_primary_idx, primary_salt)`
- `payload_commitment_v2 = Poseidon(primary_commitment, share_content_commitment_a, share_content_commitment_r)`

`js/tsip_v4_bindings.js` 同时承担 client witness field derivation 和 shuffler ordered public-signal verification。静态 gate 已验证 canonical A/R routes 接受，而 swapped A、swapped R、A/R cross-swap、changed route context 和 changed blob hash 均拒绝。

## 能支持的主张

- accepted-predecessor consistency
- K-window envelope compliance
- hidden-primary derivation
- same-primary payload and route binding
- admission-time rejection of modeled SHTPC violations

## 不能支持的主张

- 物理轨迹真实性或可信定位
- 用户来源认证或设备未被攻陷
- 对所有 in-envelope false reports 的检测
- 无条件匿名性或 metadata leakage 消失
- 生产级 setup ceremony、密钥管理、运维或完整系统安全

## 证据分层

- 22/22 static gate 支撑 circuit compatibility 和 tamper rejection。
- 5/5 small Docker smoke 支撑 protocol pipeline 可执行。
- fixed utility 支撑五数据集效用和公平 baseline 比较。
- N=1000 paper-scale matrix 已完成 15/15 execution pass，但只有 strict aggregate 验证全部单元后才能支撑当前 relation 的 latency/throughput 结论。

## 2026-07-14 证据边界收敛

- N=1000 paper-scale execution 已于 2026-07-13 23:24:37 +0800 完成 15/15 pass，failed units 为 0；13/15 只是历史运行中快照，不得再作当前状态。
- launcher pass 只支撑“全部执行单元结束”，不直接支撑 latency、throughput 或零失败总计；这些仍须通过 strict aggregate 逐单元绑定。
- Task 9 claim map 共 27 项：17 `supported`、7 `analytical`、2 `assumption`、1 `partial`、0 `unsupported`。唯一 partial CE23 是当前 relation 的规模延迟/吞吐证据。
