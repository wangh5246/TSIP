Why RiseFL fails: RiseFL verifies each location independently using a chi-squared test on the inner product with a random vector. It has no memory across time windows — it cannot link ID_Alice at t=0 with ID_Alice at t=1. Swapping IDs or teleporting across windows passes all single-step checks.
② TSIP Interception — Commitment Chain + ZK Proof

TSIP binds each submission to a cryptographic commitment chain. Violating trajectory continuity breaks the chain — and the ZK proof verification fails.

1Commitment at t=0:  User commits to location x₀ with a blinding factor r₀:  C₀ = Commit(x₀, r₀) = Poseidon(x₀ ‖ r₀)
2Chain link at t=1:  New commitment must reference the previous:  C₁ = Commit(x₁, r₁, C₀)
3ZK Proof of continuity:  User proves (without revealing x₀ or x₁):  ‖x₁ − x₀‖ ≤ v_max · Δt
4Aggregator verifies:  Chain hash matches + Groth16 proof valid → accept; otherwise → reject

Key property (Soundness): A malicious user who swaps IDs cannot produce a valid ZK proof for the new commitment, because they don't know the blinding factor r₀ of the previous window's commitment. Forging the commitment requires breaking collision-resistance of Poseidon hash. Detection probability: ≥ 1 − 2−128
